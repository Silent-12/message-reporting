# 目标 03：事件与加密发送

> 状态：规划，依赖[目标 01](目标01-协议与安全边界.md)和[目标 02](目标02-CID与上报策略.md)。

## 目标与职责

SDK 将内部错误事件整理、限制体积、加密并异步发送；服务端按共同协议校验签发、上报策略、认证标签、时间窗口及去重。此目标先以内部测试事件验证，不新增任意业务 JSON 上报 API，也不宣称已经自动捕获错误。

## 接口与行为约定

- 加密事件至少包含 `schemaVersion: 1`、`eventId`、`appId`、由 SDK 自动提供的 `sdkVersion`、`occurredAt`、`kind` 和 `message`；不要求接入方提供应用构建版本。`kind` 为 `javascript`、`unhandledrejection` 或 `resource`。可选 `name`、`stack`、去除查询和片段后的页面路径、来源 URL 与行列号；仅在实际可获得时提供。明文中的 `eventId`、`appId` 必须与信封一致。
- 初始化中或失败、被拒绝、停止状态下的事件直接丢弃，不缓存、不发送。允许状态下每个事件新建 ID，发送时设置信封 `sentAt`，按目标 01 生成密钥、IV、AAD 和密文；仅采用 Fetch JSON POST。`CID_INVALID` 和 `NOT_ALLOWED` 按目标 02 切换状态。
- 两端使用 HKDF-SHA-256 独立派生每条事件的 32 字节子密钥：IKM 为解码后的 CID，salt 为 UTF-8 `message-reporting/v1`，info 为 UTF-8 `aes-256-gcm:` + `appId` + `:` + 规范编码的 `eventId`。AES-GCM 使用新生成的 12 字节随机 IV 和 128 位标签；AAD 及信封编码严格按目标 01。不能按 CID 缓存一个长期 AES 密钥，同一派生密钥下不重复使用 IV；不同事件子密钥不按 CID 范围拒绝相同 IV，不永久累积 CID 的 IV 列表。
- 同一 CID 不设累计事件额度，不因累计条数失效；服务端仍验证签发、归属、撤销状态、上报策略及请求频率，并对 `(appId,cid,eventId)` 原子去重。必要安全校验组件不可用时返回 503，不降级放行。
- 明文 JSON 上限 32 KiB（UTF-8 字节），服务端及 SDK 的完整信封上限 48 KiB。先对消息、堆栈、URL、上下文做有界裁剪，保持合法 JSON 和必需字段；仍超限或无法安全序列化时丢弃。不得直接序列化 DOM、循环对象或任意异常值；Promise 拒绝值按可安全描述的有限字段归一化。
- 每次请求超时 5 秒；网络错误、超时和 5xx 按 1、2、4 秒指数退避最多重试 3 次，4xx（含 429）及无效响应不重试。重试原样复用同一加密信封，不重算密钥、IV、时间或事件 ID；收到 `409 REPLAYED` 停止且结果未知。最多同时存在 5 个实际未结束的上报请求；超时后尝试中止，只有请求实际结束才释放并发额度，重试到时无额度则停止该事件。无离线队列、无通道切换，关闭页面或断网时允许丢失；完整规则见目标 01。
- 避免采集 SDK 自身发送和上下文回调造成的错误；所有内部异步任务都处理拒绝，不能制造未处理 Promise 或递归上报。服务端成功返回 HTTP 200 的统一包裹及 `data:null`，仅代表协议约定的接收成功，不保证后续持久化；网络异常、中止及超时可能发生在服务端处理之后，结果未知。4xx 解析 `data.errorCode`，5xx 的 `data:null` 按状态归一为 `TEMPORARY_FAILURE`；没有明确协议错误码的普通 401 不删除 CID。

## 失败处理与验收

- 服务端校验密文、标签、绑定、授权、时间戳及事件 ID，拒绝无效请求；拒绝结果和审计不记录明文载荷、CID 或密钥。签发、上报策略和服务端拒绝各类限流后的事件不应产生无界重试。
- 目标 01 的公开向量仅验证独立加密计算；本目标还须用实际发送实现覆盖普通事件、不同事件子密钥、缺失堆栈、非 Error 拒绝值、循环值、超长与多字节文本、无效 JSON、加密失败、并发饱和、每次 5 秒超时、1/2/4 秒退避、3 次重试上限、4xx 不重试、原信封复用、响应丢失后 409、停止及迟到响应。验证请求与协议固定向量一致、成功/失败语义明确且无未处理 Promise。
- 联调验证服务端真实性能、原子去重和实际持久化语义；不同浏览器下的关闭页面、网络中断和取消能力在验证前不作可靠投递承诺。
