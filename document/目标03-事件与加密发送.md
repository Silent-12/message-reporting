# 目标 03：事件与加密发送

> 状态：内部发送及后端接收落库已实现；真实基础设施与浏览器联调待验证。依赖[目标 01](目标01-协议与安全边界.md)和[目标 02](目标02-CID与上报策略.md)。

## 目标与职责

SDK 将内部错误事件整理、限制体积、加密并异步发送；服务端按共同协议校验签发、上报策略、认证标签、时间窗口及去重。此目标先以内部测试事件验证，不新增任意业务 JSON 上报 API，也不宣称已经自动捕获错误。

## 接口与行为约定

- 加密事件至少包含 `schemaVersion: 1`、`eventId`、`appId`、由 SDK 自动提供的 `sdkVersion`、`occurredAt`、`kind` 和 `message`；不要求接入方提供应用构建版本。`kind` 为唯一的错误类型标识：`javascript` 为 JS 运行错误，`unhandledrejection` 为未处理 Promise 拒绝，`img` 为图片加载错误，`script` 为脚本资源加载错误，`resource` 为其他或无法细分的资源加载错误，`other` 为其他错误。可选 `level`、环境信息、`context`、`name`、`stack`、去除查询和片段后的页面路径、来源 URL 与行列号；仅在实际可获得时提供。环境信息与 `context` 的采集、限制和失败行为见[目标 05](目标05-环境与自定义上下文.md)。明文中的 `eventId`、`appId` 必须与信封一致。
- 初始化中或失败、被拒绝、停止状态下的事件直接丢弃，不缓存、不发送。允许状态下每个事件新建 ID，发送时设置信封 `sentAt`，按目标 01 生成密钥、IV、AAD 和密文；仅采用 Fetch JSON POST。`CID_INVALID` 和 `NOT_ALLOWED` 按目标 02 切换状态。
- 两端使用 HKDF-SHA-256 独立派生每条事件的 32 字节子密钥：IKM 为解码后的 CID，salt 为 UTF-8 `message-reporting/v1`，info 为 UTF-8 `aes-256-gcm:` + `appId` + `:` + 规范编码的 `eventId`。AES-GCM 使用新生成的 12 字节随机 IV 和 128 位标签；AAD 及信封编码严格按目标 01。不能按 CID 缓存一个长期 AES 密钥，同一派生密钥下不重复使用 IV；不同事件子密钥不按 CID 范围拒绝相同 IV，不永久累积 CID 的 IV 列表。
- 同一 CID 不设累计事件额度，不因累计条数失效；服务端仍验证签发、归属、撤销状态、上报策略及请求频率，并对 `(appId,cid,eventId)` 原子去重。必要安全校验组件不可用时返回 503，不降级放行。
- 明文 JSON 上限 32 KiB（UTF-8 字节），服务端及 SDK 的完整信封上限 48 KiB。先对消息、堆栈、URL 做有界裁剪；序列化后仍超限时先移除 `context`，再移除环境信息，最后按 JSON 编码字节数缩短堆栈，保留其前部；基础事件仍超限或无法安全序列化时丢弃。不得直接序列化 DOM、循环对象或任意异常值；Promise 拒绝值按可安全描述的有限字段归一化。
- 每次请求超时 5 秒；网络错误、超时和 5xx 按 1、2、4 秒指数退避最多重试 3 次，4xx（含 429）及无效响应不重试。重试原样复用同一加密信封，不重算密钥、IV、时间或事件 ID；收到 `409 REPLAYED` 停止且结果未知。最多同时存在 5 个实际未结束的事件准备任务及 5 个实际未结束的上报请求；加密任务无法取消时，停止后仍占准备额度直到任务结束；两种额度均跨初始化代次保留，重新初始化不重置。超时后尝试中止，只有请求实际结束才释放并发额度，重试到时无额度则停止该事件。无离线队列、无通道切换，关闭页面或断网时允许丢失；完整规则见目标 01。
- 避免采集 SDK 自身发送和上下文回调造成的错误；所有内部异步任务都处理拒绝，不能制造未处理 Promise 或递归上报。服务端成功返回 HTTP 200 的统一包裹及 `data:null` 表示事件明文已与唯一去重约束一并提交到 MySQL；网络异常、中止及超时可能发生在服务端处理之后，结果未知。4xx 解析 `data.errorCode`，5xx 的 `data:null` 按状态归一为 `TEMPORARY_FAILURE`；没有明确协议错误码的普通 401 不删除 CID。

## 失败处理与验收

- 服务端校验密文、标签、绑定、授权、时间戳及事件 ID，拒绝无效请求；拒绝结果和审计不记录明文载荷、CID 或密钥。签发、上报策略和服务端拒绝各类限流后的事件不应产生无界重试。
- 目标 01 的公开向量仅验证独立加密计算；本目标还须用实际发送实现覆盖普通事件、不同事件子密钥、缺失堆栈、非 Error 拒绝值、循环值、超长与多字节文本、无效 JSON、加密失败、并发饱和、每次 5 秒超时、1/2/4 秒退避、3 次重试上限、4xx 不重试、原信封复用、响应丢失后 409、停止及迟到响应。验证请求与协议固定向量一致、成功/失败语义明确且无未处理 Promise。
- 联调验证服务端真实性能、原子去重和实际持久化语义；不同浏览器下的关闭页面、网络中断和取消能力在验证前不作可靠投递承诺。

## 实现和存储边界

- 内部事件允许可选 `level`（`debug`、`info`、`warn`、`error`）、`environment: { userAgent?, online?, effectiveType? }`、`name`、`stack`、`pagePath` 和 `source: { url?, line?, column? }`；服务端拒绝其他字段。环境信息中 UA 与网络类型分别最多 1024 和 64 个 UTF-8 字节，`online` 为布尔值；SDK 会裁剪超长字符串，服务端拒绝超限输入。SDK 对消息、堆栈、名称和 URL 的裁剪上限分别为 8192、16384、1024 和 2048 个 UTF-8 字节；`Error` 拒绝值归一化为「名称: 消息」，其他对象类型记为 `[object]`。SDK 生成的 `pagePath` 与 `source.url` 去除查询和片段；服务端不对这两个字段做此类处理，校验通过后原样保存。SDK 会安全读取 `navigator.userAgent`、`navigator.onLine` 与 `navigator.connection.effectiveType` 自动补充环境字段，显式传入值优先；`getContext` 结果经有界归一化后作为独立 `context` 字段发送，限制与失败行为见目标 05。
- `log_report_event` 直接保存 CID，并分别保存级别、`kind`、消息、环境信息 JSON（`extra_info`）、自定义上下文 JSON（`context_info`）和完整明文 JSON；未提供级别时存储 `error`，未提供环境信息或上下文时对应列为 `NULL`，不会改写完整明文。`(cid,eventId)` 区分大小写的唯一索引与插入同事务完成去重。事件限流为每 IP 每分钟 120 次，Redis 不可用返回 503。暂不提供查询接口或自动删除，实际数据保留与访问策略上线前确定。
- 目标 03 完成时内部发送函数尚无公开调用方，当时发布构建会移除该未使用函数，事件只能通过测试专用构建注入验证；目标 04 已将其接入公开调用链，当前构建产物包含 `/v1/events` 与事件发送代码。
