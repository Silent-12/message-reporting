# 目标 03：事件与加密发送

> 状态：规划，依赖[目标 01](目标01-协议与安全边界.md)和[目标 02](目标02-CID与准入.md)。

## 目标与职责

SDK 将内部错误事件整理、限制体积、加密并异步发送；服务端按共同协议校验签发、准入、认证标签、时间窗口及去重。此目标先以内部测试事件验证，不新增任意业务 JSON 上报 API，也不宣称已经自动捕获错误。

## 接口与行为约定

- 加密事件至少包含 `schemaVersion: 1`、`eventId`、`appId`、`release`、`sdkVersion`、`occurredAt`、`kind` 和 `message`；`kind` 为 `javascript`、`unhandledrejection` 或 `resource`。可选 `name`、`stack`、去除查询和片段后的页面路径、来源 URL 与行列号；仅在实际可获得时提供。明文中的 `eventId`、`appId` 必须与信封一致。
- 初始化中或失败、被拒绝、停止状态下的事件直接丢弃，不缓存、不发送。允许状态下每个事件新建 ID，发送时设置信封 `sentAt`，按目标 01 生成密钥、IV、AAD 和密文；仅采用 Fetch JSON POST。`CID_INVALID` 和 `NOT_ALLOWED` 按目标 02 切换状态。
- 明文 JSON 上限 32 KiB（UTF-8 字节），服务端及 SDK 的完整信封上限 48 KiB。先对消息、堆栈、URL、上下文做有界裁剪，保持合法 JSON 和必需字段；仍超限或无法安全序列化时丢弃。不得直接序列化 DOM、循环对象或任意异常值；Promise 拒绝值按可安全描述的有限字段归一化。
- 默认请求超时 10 秒，最多同时存在 5 个实际未结束的上报请求；超限直接丢弃。超时后尝试中止，只有请求实际结束才释放并发额度；若请求无法中止或一直不结束，额度可能耗尽。无离线队列、无自动重试、无通道切换，关闭页面或断网时允许丢失。
- 避免采集 SDK 自身发送和上下文回调造成的错误；所有内部异步任务都处理拒绝，不能制造未处理 Promise 或递归上报。HTTP 2xx 仅代表协议约定的接收成功，不保证后续持久化；网络异常、中止及超时可能发生在服务端处理之后，结果未知。

## 失败处理与验收

- 服务端校验密文、标签、绑定、授权、时间戳及事件 ID，拒绝无效请求；拒绝结果和审计不记录明文载荷、CID 或密钥。签发、准入和服务端拒绝各类限流后的事件不应产生无界重试。
- 单元与本地接收器测试覆盖普通事件、缺失堆栈、非 Error 拒绝值、循环值、超长与多字节文本、无效 JSON、加密失败、并发饱和、超时及迟到响应。验证请求与协议固定向量一致、成功/失败语义明确且无未处理 Promise。
- 联调验证服务端真实性能、原子去重和实际持久化语义；不同浏览器下的关闭页面、网络中断和取消能力在验证前不作可靠投递承诺。
