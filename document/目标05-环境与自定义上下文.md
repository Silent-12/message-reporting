# 目标 05：环境与自定义上下文

> 状态：规划，依赖[目标 01](目标01-协议与安全边界.md)和[目标 03](目标03-事件与加密发送.md)，与目标 04 集成验收。当前只有 `environment` 字段的校验、裁剪与发送通道，尚未自动采集，`getContext` 仅保存未调用；详见[完成度标注](前端错误监控目标总览.md#完成度标注2026-10-29)。

## 目标与职责

SDK 为允许上报的错误事件附加有限的浏览器和网络环境信息，并调用接入方初始化时配置的回调读取当前业务上下文；服务端按协议接收并遵守既定数据访问及留存策略。

## 接口与行为约定

- 环境字段按实际 API 能力采集，首版只包含可获得的浏览器 UA、在线状态及网络有效类型（如 `4g`）；字段缺失时省略，不推断精确网络或设备身份。目标 03 已提供 `environment` 字段及接收、存储校验，但尚未自动采集。UA 可能包含识别信息，纳入隐私告知及服务端访问控制；不得收集 Cookie、请求头、请求体、完整 URL 或本地存储全部内容。
- 初始化可配置 `getContext` 回调，无参数，每次符合上报策略且准备处理事件时调用一次，返回普通 JSON 对象或其 Promise；登录和退出后的新状态可在后续事件体现。仅作为事件内的独立 `context` 字段，不允许覆盖事件、协议、CID 或安全字段。
- 回调拒绝、抛错、返回非法值、包含循环结构或超过 1 秒未完成时，忽略本次自定义上下文，继续基础错误事件；捕获迟到 Promise 的拒绝，避免产生未处理异常。最多同时保留 5 个实际未结束的回调，超限时跳过回调并继续基础事件；超时不会取消应用的异步任务，未结束任务仍占名额，可能导致后续上下文缺失。回调不会主动修改或扫描接入方存储，由应用自行读取和脱敏所需字段。
- 环境信息及上下文与错误事件共享目标 03 的明文和信封体积限制；先限制单字段长度及对象规模，无法安全归一化时丢弃该上下文而非阻断基础事件。路径、错误内容和自定义身份数据仍可能敏感，接入方须控制字段、授权与脱敏。

## 失败处理与验收

- 覆盖浏览器无网络信息 API、离线状态、权限或属性读取异常、上下文同步/异步成功、登录状态变化、回调超时/抛错/拒绝、循环对象、超大对象及保留字段冲突。确认基础事件仍能发送且不暴露无关存储数据。
- 由接入方与服务端确认采集字段、保留期限、访问范围和删除方式；真实用户数据、各浏览器的网络信息准确性及隐私合规流程尚未验证。
