# 目标 06：接入验证与框架扩展

> 状态：规划。浏览器级验收依赖目标 01–05；框架专属接入作为浏览器级链路完成后的独立后续目标。

## 目标与职责

SDK 提供可安装的浏览器构建和文档；应用接入方提供 HTML、Vue、React 测试应用及实际框架版本；定制服务端提供协议实现和可核验的接收结果。分别记录本地接收器、真实服务端及生产构建的结果。

## 接入与验证约定

- 为模块化应用提供 ESM 与类型声明，为单 HTML 提供 IIFE；CJS 是否保留按实际构建工具需要确定。更新 README 的初始化、异步状态、停止、采集范围、服务端依赖与失败边界，检查 `package.json`、构建产物和包内容。
- 在约定浏览器中，用真实 HTML、Vue、React 应用及真实定制服务端验证 CID 签发、持久化、准入、触发三类浏览器错误、动态上下文、AES-GCM 加密、服务端校验和接收。检查禁止上报、限流、超时、重放、吊销、跨域、隐私和异常风暴。以接收端可核验结果为依据，不把请求发出或单纯 HTTP 2xx 等同于已持久化。
- 执行 `npm run check`，涉及包入口或发布内容时执行 `npm pack --dry-run`；测试前确认构建清理不会覆盖需保留的本地 `dist` 内容。源码、类型、构建和 README 的变更按项目规则分别验证。

## 独立后续目标：框架已捕获错误

- 明确实际 Vue/React 版本后，设计 Vue 错误处理器和 React Error Boundary 或 root 回调的一次性接入方式。保留应用已有处理器、错误边界与 UI 行为；不承诺覆盖业务已经吞掉的错误。
- 验证生产构建中组件渲染、生命周期等约定范围内的错误，核对组件信息可用性、浏览器与框架双重观察时的有界去重，以及原处理器调用。开发和生产构建的传播行为可能不同，不能只以开发环境验证。

## 失败处理与验收边界

- 服务端不可用、拒绝、签发限流、存储或浏览器能力缺失时，确认 SDK 不干扰宿主、不发送明文、不无界排队；逐项记录服务端部署、浏览器及框架版本和失败结果。
- 只有约定范围内的真实“触发 → 捕获 → 加密 → 服务端校验及接收”通过后，才可宣称该范围可用。框架目标通过前不宣称已捕获框架处理的全部错误；Source Map 存储与还原必须另行验证。
