# 目标 04：浏览器自动捕获

> 状态：规划，依赖[目标 02](目标02-CID与上报策略.md)和[目标 03](目标03-事件与加密发送.md)。

## 目标与职责

SDK 在可上报后监听当前窗口的浏览器级错误，并通过目标 03 异步发送；服务端按共同协议接收，不需要为每种浏览器事件提供独立接口。应用不必在每个错误发生处手动调用 SDK。

## 接口与行为约定

- 使用事件监听器捕获同步 JavaScript `error`、`unhandledrejection`、图片及脚本等资源加载错误；资源错误通过捕获阶段监听。区分脚本运行错误与资源元素错误，按实际可得信息组装 `kind`、来源及堆栈；`kind` 的取值与含义见目标 03。
- 仅在初始化时确认上报策略允许后安装监听器；初始化之前和等待上报策略查询结果期间的错误不缓存、不上报。重复初始化不重复注册；停止时仅移除 SDK 自己的监听器，停止及重新初始化遵循目标 02 的代次控制。
- 不覆盖 `window.onerror`、不调用 `preventDefault`、不停止事件传播，不改变应用已有处理器。SDK 内部异常、发送失败、回调失败不递归采集；事件风暴遵守目标 03 并发与体积限制。
- 全局监听不能覆盖已经被应用吞掉或框架处理的全部错误；跨域脚本可能仅提供受限信息。默认不采集其他 iframe、Worker、SDK 安装前的错误，也不拦截所有 `console.error` 调用。

## 失败处理与验收

- 无监听能力、安装异常或所需浏览器 API 缺失时，SDK 不应影响页面，并以可观察的初始化状态表明无法正常监控；不得宣称成功捕获。
- 在真实浏览器触发脚本运行异常、未处理 Promise 拒绝、图片与脚本资源加载失败，检查各类事件及接收结果；覆盖跨域信息受限、没有堆栈、拒绝上报、停止/重新初始化和重复注册。
- 验证宿主已有错误处理和默认行为不变、并发错误风暴有界、SDK 自身错误与网络失败不递归。当前目标尚未实现，框架专属错误与其他窗口上下文需另行验证。
