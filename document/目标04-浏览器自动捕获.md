# 目标 04：浏览器自动捕获

> 状态：源码与自动化测试已实现（2026-10-29），依赖[目标 02](目标02-CID与上报策略.md)和[目标 03](目标03-事件与加密发送.md)。真实浏览器矩阵、真实接收端联调及框架已捕获错误仍未验证，详见[实现与验证记录](#实现与验证记录2026-10-29)。

## 目标与职责

SDK 在可上报后监听当前窗口的浏览器级错误，并通过目标 03 异步发送；服务端按共同协议接收，不需要为每种浏览器事件提供独立接口。应用不必在每个错误发生处手动调用 SDK。

## 接口与行为约定

- 使用事件监听器捕获同步 JavaScript `error`、`unhandledrejection`、图片及脚本等资源加载错误；资源错误通过捕获阶段监听。区分脚本运行错误与资源元素错误，按实际可得信息组装 `kind`、来源及堆栈；`kind` 的取值与含义见目标 03。
- 仅在初始化时确认上报策略允许后安装监听器；初始化之前和等待上报策略查询结果期间的错误不缓存、不上报。重复初始化不重复注册；停止时仅移除 SDK 自己的监听器，停止及重新初始化遵循目标 02 的代次控制。
- 不覆盖 `window.onerror`、不调用 `preventDefault`、不停止事件传播，不改变应用已有处理器。SDK 内部异常、发送失败、回调失败不递归采集；事件风暴遵守目标 03 并发与体积限制。
- 全局监听不能覆盖已经被应用吞掉或框架处理的全部错误；跨域脚本可能仅提供受限信息。默认不采集其他 iframe、Worker、Shadow DOM 内部元素、SDK 安装前的错误，也不拦截所有 `console.error` 调用；同一页面加载多份 SDK 副本不在支持范围内。

## 失败处理与验收

- 无监听能力、安装异常或所需浏览器 API 缺失时，SDK 不应影响页面，并以可观察的初始化状态表明无法正常监控；不得宣称成功捕获。
- 在真实浏览器触发脚本运行异常、未处理 Promise 拒绝、图片与脚本资源加载失败，检查各类事件及接收结果；覆盖跨域信息受限、没有堆栈、拒绝上报、停止/重新初始化和重复注册。
- 验证宿主已有错误处理和默认行为不变、并发错误风暴有界、SDK 自身错误与网络失败不递归。上述真实浏览器验收尚未执行；框架专属错误与其他窗口上下文需另行验证。

## 实现与验证记录（2026-10-29）

- 新增 `src/capture.ts`：`installCapture`（`:187`）先清理上一次安装，再在 `window` 上用捕获阶段注册 `error`，并注册 `unhandledrejection`；`uninstallCapture`（`:223`）逐个移除 SDK 自己的监听器，不触碰 `window.onerror` 或宿主其他监听器。每个监听器独立移除，移除失败项保留在跟踪状态中供后续重试；仍有残留监听器时不再注册，避免同一错误被重复上报。`canCapture`（`:31`）在发起任何请求前判断窗口、监听器增删能力与 `unhandledrejection` 支持。
- `src/index.ts:115` 在能力探测阶段调用 `canCapture`：缺少浏览器采集能力时不签发 CID、不查询上报策略，直接返回 `unavailable`。`src/index.ts:158` 在仅上报策略明确允许后安装监听器，安装失败时返回 `unavailable` 且不激活内部发送目标；`src/index.ts:225` 在 `stop` 中移除监听器。初始化之前及等待上报策略期间不安装监听器，因此错误不缓存、不上报；重复初始化复用已允许状态，不重复注册。
- 三类来源均按目标 03 的 `kind` 组装：脚本运行错误为 `javascript`（`src/capture.ts:112`），未处理 Promise 拒绝为 `unhandledrejection`（`:155`），资源元素错误按标签分为 `img`、`script` 与 `resource`（`:54`、`:138`）；SVG `image` 与 HTML `img` 同为 `img`。资源错误通过捕获阶段取得；目标不是元素时按脚本运行错误处理。公共字段由 `baseInput`（`:86`）统一组装。
- 事件字段只使用实际可获得的信息：脚本错误取 `message`、`name`、`stack` 与来源 `url`/`line`/`column`；拒绝值原样交给目标 03 的归一化逻辑；资源地址依次读取 `currentSrc`、`src`、`href`、`data`，SVG 的地址读取 `href.baseVal`（`:71`）。`pagePath`、`source.url` 与资源消息复用发送器的 `cleanUrl`（`src/event.ts:152`），统一去除查询、片段并按字节上限截断；`data:`/`blob:` 地址不进入消息或来源字段，避免携带数 MB 内联内容。行列号范围由发送器统一校验，采集模块不再重复判定。目标 05 在事件准备阶段附加自动采集的环境信息与 `getContext` 上下文，不属于采集模块组装的字段。
- 去重与宿主兼容：同一浏览器事件对象只处理一次（`src/capture.ts:170`）；超出准备或请求额度的事件在组装前丢弃（`src/event.ts:365`）；不调用 `preventDefault`/`stopPropagation`，不覆盖已有处理器；采集、整理与发送异常均在监听器内吸收，不产生未处理 Promise 或递归上报。同一页面加载多份 SDK 副本仍会各自安装监听器，按约定不在支持范围内。
- 自动化验证：`tests/capture.test.mjs` 16 项，覆盖安装时机、等待期间不采集、三类事件字段、资源地址与内联地址、跨域受限或无堆栈、停止与重新初始化、重复初始化不重复注册、监听器移除与回滚失败、宿主监听器保留、同一事件对象去重、读取异常不外泄、事件风暴及组装前丢弃、网络失败不递归、缺少能力时不发起请求。`npm run check` 通过，共 63 项测试。
- 行为影响：无 `window`、无法注册监听器或不支持 `unhandledrejection` 的环境（例如 Node 直接调用、旧版 iOS Safari）初始化返回 `unavailable`，且不发起 CID 签发或上报策略请求；这是目标 04 要求的可观察失败状态。
- 仍未验证：Windows Chrome/Edge/Firefox、macOS Safari、Android Chrome 与 iOS Safari 的真实触发；真实接收端、CORS 与代理链；跨域脚本在浏览器中实际提供的信息、无堆栈场景；Shadow DOM 内部元素、iframe、Worker、`console.error`、多份 SDK 副本与初始化前的错误（按约定不采集）；框架已捕获错误（目标 06）；关闭页面、断网与请求取消失败等投递边界。
