## 目标与调整

建设面向浏览器 HTML、Vue 和 React 应用的自动错误监控 SDK，并由定制服务端按共同协议签发和校验 CID、控制上报、接收及审计事件。首版覆盖浏览器全局 JavaScript 错误、未处理 Promise 拒绝和资源加载错误；框架自行捕获的错误另列后续目标。

初始化只要求 `serverUrl` 和 `appId`，可选 `getContext`；后续事件由 SDK 自动携带自身 `sdkVersion`。CID 由 `app-pulse/backend` 签发并记录来源信息，客户端持久化复用；同一 CID 不设累计事件数上限。浏览器、网络信息和动态上下文采集属于后续目标；事件发送目前只通过内部测试注入验证，尚无自动捕获。

appId 的创建流程为：管理员通过后台项目创建接口提交项目名称 → 后端安全随机生成同时含小写字母和数字的 appId，保存项目对应关系后返回 → 接入方将其用于 SDK 初始化。appId 不含大写或特殊符号、不从项目名称派生；后台项目创建页面尚未实现。

## 共同约束

- CID 是浏览器可读取的标识，以 CID 派生的密钥不构成可信客户端身份。获取 CID 者可生成有效请求；签发记录、上报策略、限流与审计只能降低滥用风险，不能保证阻止刷写。
- 两端按 CID、appId、eventId 独立派生每条事件子密钥，无密钥查询接口。同一 CID 无累计事件额度；上报策略、人工撤销及请求频率限制保留。服务端签发记录持久化成功后才返回 CID，创建时间与来源 IP 等仅保存在受控业务记录中，不绑定后续 IP。
- 三个协议接口沿用 AppPulse 统一响应；CID、上报策略判定结果分别位于 `data.cid`、`data.allowed`。必要安全校验故障返回 503，不放行；通用访问和诊断日志不记录 CID、密钥或协议正文。
- 初始化时查询上报策略；未取得明确允许时不发送、不缓存事件。服务端对每条事件再次校验上报策略，配置变更立即生效。应用可在失败后稍后重新初始化。
- 默认仅 Fetch JSON POST；三个协议接口单次请求超时 5 秒，网络错误、超时及 5xx 按 1、2、4 秒指数退避最多重试 3 次，4xx 等明确拒绝不重试。事件重试复用原加密信封，去重冲突及超时后的结果边界见目标 01。无离线队列和旧通道兼容层；采集和发送失败不得影响宿主。
- 浏览器验收范围为 Windows Chrome/Edge/Firefox、macOS Safari、Android Chrome、iOS Safari 的验收时当前及上一稳定版；实际版本和结果按目标 01 记录，当前均未验证。移动 WebView、框架版本、生产来源/代理链和数据留存另行验收。原生微信小程序、SSR、Worker 和其他页面上下文不在首版承诺内；Source Map 不属于本轮实现。
- 已实现范围和验证结果分别记录；浏览器自动采集及完整端到端验收仍为后续工作。
