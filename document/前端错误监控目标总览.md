# 前端错误监控目标总览

> 状态：规划，尚未实现或完成服务端联调。本文及下列目标文档是后续实施入口；保留[原分阶段方案](前端错误监控分阶段调整方案.md)供追溯。

## 目标与调整

建设面向浏览器 HTML、Vue 和 React 应用的自动错误监控 SDK，并由定制服务端按共同协议签发和校验 CID、控制准入、接收及审计事件。首版覆盖浏览器全局 JavaScript 错误、未处理 Promise 拒绝和资源加载错误；框架自行捕获的错误另列后续目标。

本次决定更新原方案中“不创建或持久化长期标识”“不主动采集运行时信息”等前提：CID 由服务端签发并持久化，采集约定范围内的浏览器、网络信息，以及接入方初始化时配置的动态上下文。原方案的接口与阶段建议如与本系列冲突，以本系列为准；本系列是待实现目标，不改变当前代码事实。

## 共同约束

- CID 是浏览器可读取的标识，以 CID 派生的密钥不构成可信客户端身份。获取 CID 者可生成有效请求；签发记录、准入、限流与审计只能降低滥用风险，不能保证阻止刷写。
- 初始化时查询准入；未取得明确允许时不发送、不缓存事件。服务端对每条事件再次校验准入，配置变更立即生效。应用可在失败后稍后重新初始化。
- 默认仅 Fetch JSON POST，无自动重试、离线队列和旧通道兼容层。需完整保留既有应用错误处理行为；采集和发送失败不得影响宿主。
- 目标浏览器及最低版本、移动 WebView、框架版本、服务端部署及 Source Map 处理待联调时确认。原生微信小程序、SSR、Worker 和其他页面上下文不在首版承诺内。
- 这些文档只规划后续工作；不表示 SDK、服务端、安全控制或端到端验证已经完成。
