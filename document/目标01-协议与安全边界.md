# 目标 01：协议与安全边界

> 状态：规划。下述为供 SDK 与定制服务端实现和联调的 v1 提案，双方确认后实施；不是现有接口。

## 目标与依赖

形成可测试的签发、准入、加密事件协议和浏览器支持矩阵。无前置实现依赖；目标 2–6 均以此协议为准。服务端需配合完成签发、查询、接收、审计和限流，具体部署环境待确定。

## 接口与行为约定

- 初始化提供 `serverUrl`、服务端分配的 `appId`、应用构建版本 `release`，以及可选的上下文回调。`serverUrl` 是 HTTPS 服务根地址，可以含路径前缀；以下相对路径追加在该前缀后。仅本地 loopback 开发允许 HTTP；生产禁止明文 HTTP。`appId` 为 1–64 个 ASCII 字母、数字、`_` 或 `-`。`release` 为 1–128 个字符。
- 三个接口均为 `POST`、`Content-Type: application/json`：`v1/cids` 接收 `{appId}`，成功返回 `{cid}`；`v1/admission` 接收 `{appId,cid}`，成功返回 `{allowed: boolean}`；`v1/events` 接收下述加密信封。服务端必须校验 `appId` 与 CID 的签发归属。JSON 响应的成功状态使用 2xx；事件的 2xx 仅表示服务端已接受，具体持久化保证以服务端契约和验证结果为准。
- CID 由服务端用密码学安全随机源生成 32 字节，编码为无 `=` 填充的 base64url 字符串；服务端保证签发唯一并建立与 `appId` 的绑定。事件 ID 使用客户端安全随机源生成 16 字节并同样编码。字段按严格 base64url 格式解码，拒绝非规范编码、错误长度和未知协议版本。
- 事件信封为 `{version:1,appId,cid,eventId,sentAt,iv,ciphertext}`。`sentAt` 是加密发送时的 Unix 毫秒整数；`iv` 是 12 字节随机值，`ciphertext` 是 Web Crypto AES-GCM 输出的密文与末尾 16 字节认证标签，二者均使用无填充 base64url。错误发生时间 `occurredAt` 在加密事件中，格式同为 Unix 毫秒整数。
- 采用 HKDF-SHA-256：输入密钥材料为解码后的 32 字节 CID，salt 为 UTF-8 字符串 `message-reporting/v1`，info 为 UTF-8 字符串 `aes-256-gcm:` 拼接 `appId`，导出 32 字节 AES 密钥。AAD 为 UTF-8 编码的紧凑 JSON 数组 `[1,appId,cid,eventId,sentAt]`，按该顺序、无空白序列化；合法字段均为 ASCII，整数使用普通十进制表示。解密和标签验证失败即拒绝。
- 每条事件使用密码学安全随机源生成新的 96 位 IV。同一 CID 最多接受 2²⁰ 条事件，服务端对同一 CID 的已接受 IV 保留记录并原子拒绝重复，达到上限后吊销该 CID；明确通知客户端重新申请。随机 IV 只使碰撞概率很低，并不能数学上保证不重复；服务端拒绝重复是检测措施，不能消除碰撞发生时的加密风险。实施前双方应复核并测试这一限制；不得固定或重用 IV。
- 服务端先限制请求大小，再验证协议、CID、准入和认证标签，并校验 `sentAt` 在服务端当前时间前后各 5 分钟之内。对 `(appId,cid,eventId)` 原子去重，成功接受后至少保留 10 分钟；去重记录与事件接收必须有一致的原子语义。时间窗口由服务端配置并与去重保留期联动：保留期不少于完整接受窗口。SDK 首版不重试，重复事件拒绝不得再次写入。
- 约定错误码至少区分 `CID_INVALID`、`NOT_ALLOWED`、`RATE_LIMITED`、`REPLAYED`、`INVALID_REQUEST`、`TEMPORARY_FAILURE`；非 2xx、网络中断、无效响应和超时均不是成功。吊销或额度耗尽使用 `CID_INVALID`；服务端对每条事件重新检查准入。不能依赖客户端状态做安全决策。
- 服务端允许约定的应用来源进行 CORS 预检及 JSON POST；SDK 默认 `credentials: 'omit'`、`referrerPolicy: 'no-referrer'`。CORS 不是访问控制，直接 HTTP 客户端可绕过浏览器 CORS。准确客户端 IP 应由可信代理链获得；仅信任受控代理设置的转发头。

## 安全与隐私边界

CID 在请求中可见，任何读取 CID 的人都能派生同一密钥、解密已捕获的信封并构造新事件。AES-GCM 在这里提供协议完整性检查，但不提供对 CID 持有者的保密性或可信身份；HTTPS 负责传输保护。`appId` 同样是公开配置。恶意客户端仍可申请 CID、伪造上下文或分布式刷写；服务端限流、准入和审计不能完全解决这些问题。

限制默认采集范围，不自动发送 Cookie、认证令牌、请求体、完整 URL 查询参数或片段。消息、堆栈、路径与自定义数据仍可能包含敏感信息；接入方负责业务脱敏和授权，服务端负责访问控制、留存及删除策略。`release` 用于关联应用构建和 Source Map；Source Map 的上传、存储和还原由服务端及构建流程另行落实，不视为本 SDK 已支持。

## 失败处理与验收

- 缺少安全随机源、Web Crypto、持久化存储或必需网络能力时停止上报，不降级明文、不影响宿主。浏览器 Web Crypto 需要安全上下文；最低浏览器、WebView 和 API 矩阵须由实际应用确认。
- 使用独立的 SDK 与服务端实现固定测试向量，核对 CID 解码、HKDF、AAD、密文、标签及篡改拒绝；测试并发重复 ID/IV、过期和未来时间、时间偏差、CID 吊销、额度耗尽、拒绝准入和跨域预检。
- 完成真实服务端联调并记录验收前，不宣称认证、防重放、加密或 Source Map 能力已上线。安全审计及浏览器矩阵尚未完成。
